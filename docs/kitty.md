# Kitty в Phoenix 1.1

Подробный сбор **выключен по умолчанию**. Phoenix не меняет `kitty.conf` и не включает управление Kitty самостоятельно. Без доступа к Kitty продолжает работать прежний fallback: обычное окно или один однозначно определённый локальный shell-каталог.

## Временная настройка для проверки

В пользовательской графической сессии создайте закрытый каталог и запустите отдельный Kitty:

```bash
install -d -m 700 "$XDG_RUNTIME_DIR/phoenix-kitty"
kitty -o allow_remote_control=socket-only \
  --listen-on "unix:$XDG_RUNTIME_DIR/phoenix-kitty/kitty.sock"
```

В Phoenix откройте «Настройки», включите сбор подробной структуры Kitty и укажите **абсолютный путь** к сокету, например `/run/user/1000/phoenix-kitty/kitty.sock` (подставьте свой UID). Либо передайте путь процессу Phoenix через `PHOENIX_KITTY_SOCKET`. Сокет и непосредственно содержащий его каталог должны принадлежать пользователю; каталог должен иметь права 0700. Временный каталог может потребоваться создать заново после входа.

`socket-only` разрешает контроль Kitty любому процессу с доступом к сокету, включая отправку команд и чтение терминала. Закрытый каталог защищает от других пользователей, но не от процессов того же пользователя. Эта команда меняет настройки только запускаемого экземпляра Kitty; Phoenix сам её не запускает. Режимы Kitty с паролем Phoenix пока не поддерживает: пароли не запрашиваются и не сохраняются.

Для надёжного сопоставления в текущей версии должен быть ровно один Kitty OS-window в Hyprland и ровно один OS-window в ответе сокета; PID сокета проверяется через `SO_PEERCRED`. При неоднозначности подробное состояние пропускается. Это ограничение Wayland: `platform_window_id` может отсутствовать. Обычное восстановление окон остаётся доступным.

## Архив текста

Отдельно включите «Архивировать текст терминала» в настройках. Это явный opt-in: в текст могут попасть **пароли, токены, переписка и другие личные данные**. Phoenix не умеет гарантированно распознавать секреты. Файлы защищены правами пользователя, но не шифруются. SQLite WAL, свободные страницы и резервные копии тоже могут содержать текст даже после его удаления из текущей базы.

Сохраняется текст, доступный Kitty через `get-text --extent all`, без ANSI-стилей. По умолчанию лимит — 32 МиБ несжатого текста на панель, 1 ГиБ сжатых уникальных блоков в базе. При превышении лимита панели сохраняется доступный хвост и выдаётся предупреждение; если превышен ограниченный бюджет входа или время запроса, панель пропускается. На один проход сбора общий бюджет удерживаемого текста — 64 МиБ; при его исчерпании остальные панели пропускаются. Блоки сжимаются и дедуплицируются, их целостность проверяется; ротация снимков удаляет невостребованные блоки. Лимит архива не включает накладные расходы SQLite и резервные копии. При заполнении квоты новые панели могут быть пропущены.

В настройках можно задать лимиты и удалить архивы из текущей базы. Через CLI:

```bash
./phoenix.sh archive list latest
# Индексы окна, вкладки и панели в CLI начинаются с нуля:
./phoenix.sh archive show latest 0 0 0
./phoenix.sh archive purge --confirm
```

Для просмотра в GUI выберите снимок и нажмите «Архив терминала». Большие архивы в GUI показываются с ограничением первых 256 КиБ; CLI позволяет прочитать весь сохранённый текст. Управляющие символы фильтруются. Это исторический текст, не запущенный процесс. Удаление в Phoenix не очищает резервные копии и не гарантирует физическое стирание из SQLite/WAL или с носителя.

Необязательные исключения в `~/.config/phoenix/config.json`:

```json
{
  "kitty_exclude_panels": [42],
  "kitty_exclude_text": ["фраза-для-исключения"]
}
```

Первое — числовые Kitty panel ID **текущего процесса**, которые могут измениться после перезапуска. Второе — буквальные подстроки: при совпадении архив всей панели пропускается. Список оконных классов `exclude_classes` по-прежнему исключает Kitty целиком. Это не защита от всех возможных утечек секретов.

## Восстановление и проверка

1. Настройте сокет и включите подробный сбор. Для проверки архива отдельно включите сбор текста.
2. Создайте в тестовом Kitty несколько вкладок и панелей, откройте разные каталоги.
3. Выполните `./phoenix.sh snapshot --name "Kitty test"`, затем `./phoenix.sh inspect latest` и `./phoenix.sh restore latest --dry-run`.
4. В GUI откройте «Приложения» и выберите панели. План показывает зависимости и недоступные запущенные программы. Архив открывается отдельно и не передаётся shell.
5. В отдельной тестовой сессии закройте только тестовый Kitty и выполните восстановление. Повторите восстановление: Phoenix должен сопоставить открытое окно и не запускать его повторно.

Создаются новые shell-панели, расположение и активные элементы восстанавливаются по сохранённым layout и порядку. Точная геометрия splits, работающие программы, SSH-соединения и память процессов не восстанавливаются. Нельзя воспроизвести произвольные команды из снимка, даже подтвердив их: эти шаги помечены недоступными. Если окно уже открыто, его вкладки и панели не изменяются. При аварии после запуска повторное создание окна подавляется до проверки пользователем. Журнал шагов: `./phoenix.sh recovery-log latest`.

## Миграция и возврат на 1.0

Первый запуск Phoenix 1.1 обновляет схему базы с 4 до 5 добавлением таблиц; существующие снимки остаются доступны. Старый исполняемый код 1.0 откажется открывать схему 5. Перед проверкой 1.1 сохраните проверенную резервную копию из работающей версии 1.0 или используйте отдельные XDG-каталоги. При возврате к 1.0 потребуется восстановить копию базы версии 4; изменения, созданные после этой копии, в ней отсутствуют. Не заменяйте рабочую базу, пока Phoenix или другое приложение подключено к ней.
