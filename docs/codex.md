# Проверка конкретной сессии Codex CLI

Экспериментальная команда **не восстанавливает разговор и не определяет, какая панель Kitty с ним связана**. Она проверяет указанные пользователем UUID и каталог проекта через локальный Codex app-server. Разговор «последний» автоматически не выбирается.

```bash
./phoenix.sh codex-check 00000000-0000-4000-8000-000000000000 --cwd /абсолютный/путь/к/проекту
```

При успехе вывод содержит `metadata_verified`, нормализованный путь и массив `resume_argv`. Он означает лишь совпадение ID и каталога в ответе локального Codex и то, что сессия не помечена как ephemeral. Запуск `codex resume` и фактическое возобновление не проверяются. Если пользователь сам решил открыть этот разговор, он может перейти в показанный каталог и выполнить показанную команду; Phoenix не запускает её автоматически. Проверка не доказывает связь ID с конкретным окном или панелью.

Используется `thread/read` с `includeTurns: false`; полные сообщения не запрашиваются, возможный краткий preview не выводится и не записывается Phoenix. Аргументы процессов и историю терминала не читаем. UUID и каталог могут быть чувствительными данными, поэтому не направляйте вывод команды посторонним. Процесс app-server запускается только по явной команде пользователя, с ограничением времени и размера ответа; аналитика для него отключается через настройку. Сам Codex использует свою пользовательскую конфигурацию и хранилище и может создавать собственные служебные файлы. Phoenix не меняет свою базу при этой проверке.

Основа: [документация Codex app-server](https://developers.openai.com/codex/app-server/) и `codex resume --help` установленной версии. Следующий необходимый шаг — доказуемо связать конкретную панель с ID разговора и предусмотреть явную политику восстановления без подстановки случайного ID.
