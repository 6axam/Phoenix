# Проверка конкретной сессии Codex CLI

Экспериментальная команда **не восстанавливает разговор и не определяет, какая панель Kitty с ним связана**. Она проверяет указанные пользователем UUID и каталог проекта через локальный Codex app-server. Разговор «последний» автоматически не выбирается.

```bash
./phoenix.sh codex-check 00000000-0000-4000-8000-000000000000 --cwd /абсолютный/путь/к/проекту
```

При успехе вывод содержит `metadata_verified`, нормализованный путь и массив `resume_argv`. Он означает лишь совпадение ID и каталога в ответе локального Codex и то, что сессия не помечена как ephemeral. Запуск `codex resume` и фактическое возобновление не проверяются. Если пользователь сам решил открыть этот разговор, он может перейти в показанный каталог и выполнить показанную команду; Phoenix не запускает её автоматически. Проверка не доказывает связь ID с конкретным окном или панелью.

Используется `thread/read` с `includeTurns: false`; полные сообщения не запрашиваются, возможный краткий preview не выводится и не записывается Phoenix. Аргументы процессов и историю терминала не читаем. UUID и каталог могут быть чувствительными данными, поэтому не направляйте вывод команды посторонним. Процесс app-server запускается только по явной команде пользователя, с ограничением времени и размера ответа; аналитика для него отключается через настройку. Сам Codex использует свою пользовательскую конфигурацию и хранилище и может создавать собственные служебные файлы. Phoenix не меняет свою базу при этой проверке.

Основа: [документация Codex app-server](https://developers.openai.com/codex/app-server/) и `codex resume --help` установленной версии. Следующий необходимый шаг — доказуемо связать конкретную панель с ID разговора и предусмотреть явную политику восстановления без подстановки случайного ID.

## Явная привязка к панели Kitty

Это экспериментальная возможность с отдельным opt-in. В Phoenix нужно включить подробный сбор Kitty, настроить приватный сокет и включить настройку «Сохранять явные привязки Codex к панелям Kitty» (`kitty_codex_bindings`). При обычном запуске Codex Phoenix не угадывает ID по последнему разговору.

Чтобы явно привязать и открыть конкретный разговор, выполните **в нужной панели Kitty**:

```bash
./phoenix.sh codex-resume UUID --cwd /абсолютный/путь/к/проекту
```

Если метаданные ID и проекта совпадают, команда запускает ровно `codex resume UUID`. Пока этот дочерний процесс работает в текущей панели, Phoenix может сохранить ID и признак явной привязки в следующий снимок. Для подтверждения связи при сборе проверяются текущие процессы, их родство и время запуска, foreground-процесс Kitty и каталог. PID и времена запуска не сохраняются; они не используются после перезагрузки. При остановке Codex или несоответствии привязка не собирается. UUID и путь проекта входят в снимок и резервные копии и могут быть чувствительными.

После перезапуска можно **вручную в выбранной панели Kitty** вызвать:

```bash
./phoenix.sh codex-restore ID_СНИМКА ИНДЕКС_ОКНА ИНДЕКС_ВКЛАДКИ ИНДЕКС_ПАНЕЛИ
```

Индексы начинаются с нуля; `latest` допустим вместо ID. Команда читает сохранённый ID и каталог, повторно проверяет их через Codex и запускает `codex resume` в той панели, где пользователь явно её вызвал. Она не определяет автоматически, что другая копия того же разговора уже открыта; проверьте это перед ручным запуском. Запуск планировщиком, автоматический ввод в терминал и автоматическое повторение после прерывания не реализованы. Само наличие привязки подтверждает явно инициированный запуск, но не гарантирует, что Codex успешно загрузил разговор. Если обёртка завершилась аварийно, устаревшая метка игнорируется при следующем сборе.
