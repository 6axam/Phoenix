# Архитектура

`Collector` получает JSON clients/workspaces/monitors через `hyprctl`; `HyprlandBackend` реализует запросы и Lua-диспетчеры 0.55+. Для событий смены рабочего стола используется socket2 с задержкой, ограничением частоты и повторным подключением; периодические снимки продолжаются при недоступности socket2. `SnapshotManager` хранит канонический JSON и SHA-256 в SQLite WAL/FULL; блокировка flock и транзакции сериализуют записи, автоматические снимки ротируются по настраиваемому лимиту, ручные и закреплённые остаются. Версия схемы в `user_version`, предусмотрены переходы 0→1→2→3→4 и отказ от неизвестных новых версий. Целостность строки проверяется при чтении; `latest` пропускает повреждённые строки. Повреждение всей базы автоматически не исправляется. Сжатые JPEG хранятся в SQLite с дедупликацией по SHA-256 и удаляются при ротации последней ссылки. При неизменном содержимом и изображениях обновляется checked, что всё равно создаёт небольшую запись.

`RecoveryPlanner` выполняет предварительное сопоставление по классу, `RecoveryExecutor` управляет сериализованной попыткой и сохраняет результаты. `DesktopRegistry` ищет root-owned desktop entries или пользовательские файлы с явно сохранённым отпечатком; запись группе и остальным запрещена. Идентификаторы старых окон и PID в снимок не попадают. Маркер решения привязан к подписи экземпляра Hyprland. GTK работает отдельно от восстановительного потока. История и база находятся в XDG DATA, конфигурация в XDG CONFIG, блокировки и маркеры в XDG STATE.

Копирование SQLite выполняется через online backup API с проверкой integrity_check; три копии ротируются отдельно от снимков. Резервные копии могут содержать изображения и личные данные.
