# Архитектура

`Collector` получает JSON clients/workspaces/monitors через `hyprctl`; `HyprlandBackend` реализует запросы и Lua-диспетчеры 0.55+. Для событий смены рабочего стола используется socket2 с задержкой, ограничением частоты и повторным подключением; периодические снимки продолжаются при недоступности socket2. `SnapshotManager` хранит канонический JSON и SHA-256 в SQLite WAL/FULL; блокировка flock и транзакции сериализуют записи, автоматические снимки ротируются по настраиваемому лимиту, ручные и закреплённые остаются. Версия схемы в `user_version`, предусмотрены переходы 0→1→2→3→4→5 и отказ от неизвестных новых версий. Целостность строки проверяется при чтении; `latest` пропускает повреждённые строки. Повреждение всей базы автоматически не исправляется. Сжатые JPEG хранятся в SQLite с дедупликацией по SHA-256 и удаляются при ротации последней ссылки. При неизменном содержимом и изображениях обновляется checked, что всё равно создаёт небольшую запись.

`RecoveryPlanner` выполняет предварительное сопоставление по классу, `RecoveryExecutor` управляет сериализованной попыткой и сохраняет результаты. `DesktopRegistry` ищет root-owned desktop entries или пользовательские файлы с явно сохранённым отпечатком; запись группе и остальным запрещена. Идентификаторы старых окон и PID в снимок не попадают. Маркер решения привязан к подписи экземпляра Hyprland. GTK работает отдельно от восстановительного потока. История и база находятся в XDG DATA, конфигурация в XDG CONFIG, блокировки и маркеры в XDG STATE.

Копирование SQLite выполняется через online backup API с проверкой integrity_check; три копии ротируются отдельно от снимков. Резервные копии могут содержать изображения и личные данные.

## Phoenix 1.1: адаптеры

`ApplicationAdapter` и встроенный `AdapterRegistry` определяют сопоставление, доступность, валидацию, сериализацию, план и разрешённое выполнение. Адаптер Kitty сохраняет только нормализованные данные вкладок/панелей; команды, переменные окружения, заголовки и пароли сокета не сериализуются. `GenericAdapter` сохраняет совместимый fallback системного desktop entry. Шаги плана содержат зависимости, доступность и отметку необходимости подтверждения; восстановление процессов заведомо недоступно. Существующий журнал запусков дополнен таблицей шагов без содержимого терминала.

Миграция SQLite 4→5 только добавляет таблицы архивных блоков, манифестов, ссылок и шагов. Запись связана с сохранением снимка одной транзакцией. Неизменившийся снимок с неизменившимися архивами повторно не записывается. Kitty не предоставляет надёжной недорогой версии scrollback, поэтому при включённом сборе текст повторно запрашивается и затем дедуплицируется. Ограничения ввода, памяти и времени не устраняют всех затрат на чтение большого терминального буфера.

### Надёжность миграции и нескольких окон

Диагностика схемы 4 работает через read-only соединение. Перед миграцией 4→5 проверяются наличие старого daemon и `integrity_check`, затем отдельная копия в `backups/migrations/` создаётся SQLite Backup API, проверяется и синхронизируется с диском; DDL выполняется одной транзакцией. Блокировка daemon относится к обычному XDG-сеансу; не используйте несовпадающие XDG-каталоги состояния для одной базы.

Сокеты Kitty обрабатываются раздельно, их peer PID и адрес живого окна проверяются повторно в ходе сбора; PID и адрес в снимок не записываются. Несколько окон одного процесса не сопоставляются по порядку. Для новых окон восстановления PID дочернего процесса используется только для ожидания соответствующего окна в текущей попытке. При уже открытых неоднозначных окнах запуск и перемещение Kitty пропускаются.

Статус сбора каждой панели согласуется с результатом записи: `saved`, `truncated`, `excluded`, `quota_exceeded`, `failed`; старые отсутствующие или удалённые архивы при чтении помечаются `not_saved`. Повреждение содержимого проверяется при чтении, а не при каждом отображении метаданных. Архивные блоки дедуплицируются; при полной квоте повторная компрессия новых блоков пропускается, но безопасного признака неизменившегося scrollback для пропуска `get-text` нет.
